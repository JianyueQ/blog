# 接入第三方登录 - 开发文档

> 日期：2026-05-29
> 
> 目标：将第三方登录配置（Gitee / GitHub / QQ）从 **yml 静态配置** 迁移至 **数据库动态管理**，支持后台修改配置，前台和后台均可通过免登录接口获取已启用的第三方登录配置信息（含图标），用于动态显示登录图标。
> 
> **约束**：第三方登录方式固定为 Gitee / GitHub / QQ 三种，**不允许新增和删除**，仅允许修改已有配置（如 appId、appSecret、回调地址、状态等）。

---

## 一、现状分析

### 1.1 当前架构

- **配置方式**：第三方登录参数（appId、appSecret、redirectUrl）写在 `application-dev.yml` 中
- **配置类**：通过 `@ConfigurationProperties` 注入到 Java Bean
  - `GiteeConfigProperties`（prefix = "gitee"）
  - `GithubConfigProperties`（prefix = "github"）
  - `QqConfigProperties`（prefix = "qq"）
  - `WeiboConfigProperties`（prefix = "weibo"）
  - `WechatProperties`（prefix = "wechat"）—— 微信公众号/小程序，**不在此次改动范围**
- **使用方**：`AuthServiceImpl.getAuthRequest()` 根据 source 参数从对应 Properties 类读取配置，构建 `AuthRequest`
- **前端**：前台 `blog-web/src/views/Login/index.vue` 和后台 `blog-admin/src/views/login/index.vue` 登录页硬编码第三方登录图标和类型

### 1.2 存在的问题

1. 修改第三方登录参数需要重启服务
2. 无法在后台管理界面动态管理第三方登录配置
3. 前端登录方式图标硬编码，无法根据后台配置动态显示/隐藏
4. 无法灵活控制某种第三方登录方式的启用/禁用

## 二、数据库设计

### 2.1 表结构：`sys_third_party_config`

> 已存在于数据库中，无需新建表。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | bigint (PK, AUTO_INCREMENT) | 主键ID |
| `config_key` | varchar | 配置键名：`github` / `gitee` / `qq` |
| `config_name` | varchar | 配置名称：`Github` / `Gitee` / `QQ` |
| `app_id` | varchar | 应用ID |
| `app_secret` | varchar | 应用密钥 |
| `redirect_url` | varchar | 回调地址（后台和前台共用） |
| `icon` | varchar | 图标URL（可上传自定义图标或使用内置图标名称） |
| `status` | int | 状态：`0` 禁用，`1` 启用 |
| `sort` | int | 排序（数值越小越靠前） |
| `create_time` | datetime | 创建时间 |
| `update_time` | datetime | 更新时间 |

### 2.2 已有数据示例

| id | config_key | config_name | icon | status | sort |
|----|-----------|-------------|------|--------|------|
| 1 | github | Github | `https://cdn.jsdelivr.net/npm/simple-icons@v12/icons/github.svg` | 1 | 1 |
| 2 | gitee | Gitee | `https://cdn.jsdelivr.net/npm/simple-icons@v12/icons/gitee.svg` | 1 | 2 |
| 3 | qq | QQ | `qq.svg` | 1 | 3 |

### 2.3 图标策略

`icon` 字段支持两种值格式：

1. **完整 URL**：如 `https://cdn.jsdelivr.net/npm/simple-icons@v12/icons/github.svg`，前端直接渲染为 `<img>` 标签
2. **内置图标名称**：如 `qq.svg`、`gitee.svg`、`github.svg`，前端匹配 `icons/svg/` 目录下的 SVG 图标组件渲染

**前端内置图标清单**（`blog-admin/src/icons/svg/`）：
- `github.svg` — GitHub 图标
- `gitee.svg` — Gitee 图标
- `qq.svg` — QQ 图标
- `wechat.svg` — 微信图标
- `chrome.svg` — Chrome 图标

前端也可通过后台管理界面**上传自定义图标**（调用文件上传接口），上传后将返回的 URL 填入 `icon` 字段。

#### 3.5.2 实现类

**文件**：`mojian-commom/src/main/java/com/mojian/service/impl/SysThirdPartyConfigServiceImpl.java`

```java
@Service
@RequiredArgsConstructor
public class SysThirdPartyConfigServiceImpl extends ServiceImpl<SysThirdPartyConfigMapper, SysThirdPartyConfig>
        implements SysThirdPartyConfigService {

    @Override
    public IPage<SysThirdPartyConfig> selectPage(SysThirdPartyConfig query) {
        LambdaQueryWrapper<SysThirdPartyConfig> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(StringUtils.isNotBlank(query.getConfigName()), SysThirdPartyConfig::getConfigName, query.getConfigName());
        wrapper.eq(query.getStatus() != null, SysThirdPartyConfig::getStatus, query.getStatus());
        wrapper.orderByAsc(SysThirdPartyConfig::getSort);
        return page(PageUtil.getPage(), wrapper);
    }

    @Override
    public SysThirdPartyConfig getByConfigKey(String configKey) {
        return baseMapper.selectOne(new LambdaQueryWrapper<SysThirdPartyConfig>()
                .eq(SysThirdPartyConfig::getConfigKey, configKey)
                .eq(SysThirdPartyConfig::getStatus, 1));
    }

    @Override
    public List<SysThirdPartyConfig> getEnabledList() {
        List<SysThirdPartyConfig> list = list(new LambdaQueryWrapper<SysThirdPartyConfig>()
                .eq(SysThirdPartyConfig::getStatus, 1)
                .orderByAsc(SysThirdPartyConfig::getSort));
        // 脱敏：只返回前端需要的字段
        list.forEach(item -> {
            item.setAppId(null);
            item.setAppSecret(null);
            item.setRedirectUrl(null);
        });
        return list;
    }

    @Override
    public boolean update(SysThirdPartyConfig config) {
        return updateById(config);
    }
}
```

#### 3.8.2 重写 getAuthRequest 方法

将原来从 Properties 读取配置改为从数据库读取：

```java
private @NotNull AuthRequest getAuthRequest(String source) {
    // 从数据库获取第三方登录配置
    SysThirdPartyConfig config = sysThirdPartyConfigService.getByConfigKey(source);
    if (config == null) {
        throw new ServiceException("未配置" + source + "第三方登录");
    }

    AuthRequest authRequest = null;
    switch (source) {
        case "gitee":
            authRequest = new AuthGiteeRequest(AuthConfig.builder()
                    .clientId(config.getAppId())
                    .clientSecret(config.getAppSecret())
                    .redirectUri(config.getRedirectUrl())
                    .build());
            break;
        case "qq":
            authRequest = new AuthQqRequest(AuthConfig.builder()
                    .clientId(config.getAppId())
                    .clientSecret(config.getAppSecret())
                    .redirectUri(config.getRedirectUrl())
                    .build());
            break;
        case "github":
            authRequest = new AuthGithubRequest(AuthConfig.builder()
                    .clientId(config.getAppId())
                    .clientSecret(config.getAppSecret())
                    .redirectUri(config.getRedirectUrl())
                    .build());
            break;
        default:
            break;
    }
    if (null == authRequest) {
        throw new AuthException("授权地址无效");
    }
    return authRequest;
}
```

> **说明**：`redirectUrl` 字段是唯一的回调地址，供后台和前台共用。

#### 5.2.1 替换硬编码的 loginTypes

将原来的静态 `loginTypes` 对象替换为动态数据：

```javascript
// 新增 import
import { getEnabledThirdPartyConfigApi } from "@/api/auth";
import { setToken } from "@/utils/cookie";

// data 中替换 loginTypes 为：
data() {
  return {
    thirdPartyConfigs: [], // 从接口动态获取已启用的第三方登录配置
    // ...
  }
}

// created 中调用：
created() {
  this.loadThirdPartyConfigs();
  this.handleCallbackToken();
}

// methods 中新增：
methods: {
  async loadThirdPartyConfigs() {
    try {
      const res = await getEnabledThirdPartyConfigApi();
      this.thirdPartyConfigs = res.data || [];
    } catch (e) {
      console.warn('加载第三方登录配置失败', e);
    }
  },
  handleCallbackToken() {
    const url = new URL(window.location.href);
    const token = url.searchParams.get('token');
    if (token) {
      setToken(token);
      url.searchParams.delete('token');
      window.history.replaceState({}, '', url.toString());
      this.$store.commit('SET_TOKEN', token);
      this.$message.success('第三方登录成功');
      this.backToHome();
    }
  },
  getIconClass(iconName) {
    const iconMap = {
      'github.svg': 'fab fa-github',
      'gitee.svg': 'fab fa-git-alt',
      'qq.svg': 'fab fa-qq',
      'github': 'fab fa-github',
      'gitee': 'fab fa-git-alt',
      'qq': 'fab fa-qq',
    };
    return iconMap[iconName] || 'fas fa-sign-in-alt';
  }
}
```

#### 5.2.3 OAuth 回调处理

在 `created` 中调用 `handleCallbackToken()`，当 OAuth 回调携带 `token` 参数时：
1. 从 URL 中提取 `token`
2. 调用 `setToken(token)` 保存到 Cookie
3. 调用 `this.$store.commit('SET_TOKEN', token)` 同步到 Vuex
4. 清理 URL 中的 token 参数
5. 提示“第三方登录成功”并跳转回首页

## 九、注意事项

1. **敏感信息保护**：公开接口必须脱敏，绝不能将 `appId`、`appSecret` 等敏感信息返回给前端
2. **禁止新增和删除**：第三方登录方式固定为 Gitee / GitHub / QQ，不允许新增和删除配置，仅允许修改已有配置的参数（如 appId、appSecret、回调地址、状态等）
3. **缓存策略**：建议对 `getEnabledList` 接口结果做 Redis 缓存（key 如 `third_party_config:enabled_list`），修改配置时清除缓存
4. **图标兼容性**：前端需同时支持 URL 图标和内置 SVG 图标两种渲染方式
5. **回调地址唯一**：只有一个 `redirect_url` 字段，供后台和前台共用，不再区分。
6. **微信公众号/小程序**：不在本次改动范围内，`WechatProperties` 保留原样
7. **数据库已有表**：`sys_third_party_config` 表已存在，无需执行建表 SQL
8. **Sa-Token 放行**：公开接口以 `/api/` 开头，已被 `SaTokenConfigure` 中的 `excludePathPatterns("/api/**")` 放行，无需额外配置
