# 前台菜单管理功能 - 开发文档

> 日期：2026-05-30
>
> 本文档描述为前台（blog-web）添加可配置的导航菜单管理功能，模仿后台已有的 `sys_menu` 菜单管理模式，使前台导航栏（Header）和移动端菜单（MobileMenu）从数据库动态加载，取代当前的硬编码方式。

---

## 一、需求分析

### 1.1 现状

| 组件 | 文件 | 数据来源 |
|------|------|----------|
| **Header 导航栏** | `blog-web/src/layout/Header/index.vue` | `data()` 中硬编码 `menuItems` 数组（10个一级菜单，含下拉子菜单） |
| **MobileMenu 移动菜单** | `blog-web/src/layout/MobileMenu/index.vue` | 从 Vue Router 的 `routes` 配置中过滤 `meta.hidden !== true` 的路由项 |
| **Vue Router** | `blog-web/src/router/index.js` | 所有路由静态定义在 `routes` 数组中 |

**存在的问题**：
- 新增/修改/删除导航菜单项必须修改前端代码并重新构建部署
- 菜单排序、显示/隐藏、图标调整均需改动源码
- 不支持外链菜单的动态配置

### 1.2 目标

- 新增 `sys_front_menu` 数据库表，存储前台导航菜单配置
- 后台管理端新增前台菜单管理页面，复用后台菜单管理的树形表格交互模式
- 前端（blog-web）的 Header 和 MobileMenu 组件改为从接口动态加载菜单数据
- Vue Router 中保留静态路由定义（含详情页、登录页等非导航菜单路由），导航菜单项的显示/隐藏/排序由接口控制

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **最小改动** | 不重构现有路由系统，仅在渲染层替换数据源 |
| **复用模式** | 后台管理页面模仿已有的 `SysMenuController` + `views/system/menu/index.vue` 模式 |
| **职责分离** | 前台菜单表独立于后台 `sys_menu`，两者互不干扰 |
| **路由兜底** | 前端保留完整静态路由定义，接口仅控制导航栏「展示哪些菜单、如何排序」 |

## 二、数据库设计

### 2.1 `sys_front_menu` — 前台菜单表

| 字段名 | 类型 | 是否必填 | 说明 |
|--------|------|----------|------|
| `id` | int (PK, AUTO_INCREMENT) | 是 | 主键 |
| `parent_id` | int | 是 | 父菜单ID，一级菜单为 0 |
| `title` | varchar(50) | 是 | 菜单显示名称（如「首页」「文章归档」） |
| `path` | varchar(200) | 是 | 路由路径（如 `/archive`）或外链 URL |
| `icon` | varchar(100) | 否 | Font Awesome 图标类名（如 `fas fa-home`） |
| `sort` | int | 是 | 显示顺序，数值越小越靠前 |
| `hidden` | tinyint | 是 | 是否在导航栏隐藏：0 显示 / 1 隐藏 |
| `is_external` | tinyint | 是 | 是否外链：0 否 / 1 是 |
| `color_class` | varchar(50) | 否 | CSS 颜色类名（如 `home-link`），用于导航项个性化样式 |
| `status` | tinyint | 是 | 状态：0 禁用 / 1 启用。禁用后不出现在接口返回中 |
| `create_time` | datetime | 自动 | 创建时间 |
| `update_time` | datetime | 自动 | 更新时间 |

**与后台 `sys_menu` 的差异**：

| 差异点 | 后台 `sys_menu` | 前台 `sys_front_menu` |
|--------|----------------|---------------------|
| 菜单类型 | 支持 CATALOG/MENU/BUTTON 三种 | 无需 BUTTON，目录即下拉分组 |
| 权限标识 | 有 `perm` 字段 | 无需权限控制，前台菜单对所有人可见 |
| 组件路径 | 有 `component` 字段 | 不需要，前端路由已静态定义 |
| 路由名称 | 有 `name` 字段 | 不需要，前端路由已定义 `name` |
| 重定向 | 有 `redirect` 字段 | 不需要 |
| 颜色类名 | 无 | 新增 `color_class` 字段，支持导航项个性化样式 |
| 状态字段 | 无（通过 hidden 控制） | 新增 `status` 字段，禁用后彻底不返回 |

### 3.7 Redis 缓存策略

前台导航菜单是高频读取、低频变更的数据（每次页面加载都会请求，但菜单变更极少），必须使用 Redis 缓存避免频繁访问数据库。

#### 3.7.1 项目现有缓存模式

项目已启用 `@EnableCaching`（`NeatAdminApplication.java`），存在两种缓存使用方式：

| 模式 | 使用场景 | 代表代码 |
|------|---------|----------|
| **Spring Cache 注解** | 配置类数据读取 | `SysThirdPartyConfigServiceImpl`（`@Cacheable` + `@CacheEvict`） |
| **RedisTemplate 直接操作** | 需要精确控制过期时间 | `SysWebConfigServiceImpl`（`RedisUtil.set`） |

前台菜单缓存采用 **Spring Cache 注解** 模式，与 `SysThirdPartyConfigServiceImpl` 保持一致。

#### 3.7.2 缓存键名设计

在 `Constants.java` 中新增常量：

```java
// Constants.java 新增
/** 前台菜单缓存名 */
public static final String CACHE_FRONT_MENU = "front_menu";
/** 前台菜单导航列表缓存键 */
public static final String CACHE_FRONT_MENU_NAV = "nav_list";
```

Redis 中实际存储的键格式：`front_menu::nav_list`（Spring Cache 默认使用 `cacheNames::key` 格式）。

#### 3.7.3 Service 层缓存注解

前台菜单的 Service 接口和实现类放在 `mojian-commom` 模块（因 `mojian-api` 和 `mojian-admin` 均需使用），缓存注解加在实现类上：

```java
package com.mojian.service.impl;

import org.springframework.cache.annotation.CacheEvict;
import org.springframework.cache.annotation.Cacheable;
import com.mojian.common.Constants;
// ...

@Service
public class SysFrontMenuServiceImpl extends ServiceImpl<SysFrontMenuMapper, SysFrontMenu>
        implements SysFrontMenuService {

    /**
     * 获取前台导航菜单列表（公开接口使用）
     * 缓存策略：Spring Cache + Redis，键名 front_menu::nav_list
     */
    @Override
    @Cacheable(cacheNames = Constants.CACHE_FRONT_MENU, key = "'" + Constants.CACHE_FRONT_MENU_NAV + "'")
    public List<FrontMenuVO> getNavList() {
        List<SysFrontMenu> menus = list(new LambdaQueryWrapper<SysFrontMenu>()
                .eq(SysFrontMenu::getStatus, 1)
                .orderByAsc(SysFrontMenu::getSort));
        return buildNavTree(menus);
    }

    /**
     * 新增菜单 — 清除缓存
     */
    @Override
    @CacheEvict(cacheNames = Constants.CACHE_FRONT_MENU, allEntries = true)
    public void addMenu(SysFrontMenu menu) {
        save(menu);
    }

    /**
     * 修改菜单 — 清除缓存
     */
    @Override
    @CacheEvict(cacheNames = Constants.CACHE_FRONT_MENU, allEntries = true)
    public void updateMenu(SysFrontMenu menu) {
        updateById(menu);
    }

    /**
     * 删除菜单 — 清除缓存
     */
    @Override
    @CacheEvict(cacheNames = Constants.CACHE_FRONT_MENU, allEntries = true)
    public void deleteMenu(Integer id) {
        if (count(new LambdaQueryWrapper<SysFrontMenu>()
                .eq(SysFrontMenu::getParentId, id)) > 0) {
            throw new RuntimeException("存在子菜单，不能删除");
        }
        removeById(id);
    }

    /**
     * 获取管理页面菜单树（不缓存，仅后台管理页面使用）
     */
    @Override
    public List<SysFrontMenu> getMenuTree() {
        // 不加缓存注解，管理页面每次都查最新数据
        List<SysFrontMenu> menus = list(new LambdaQueryWrapper<SysFrontMenu>()
                .orderByAsc(SysFrontMenu::getSort));
        Map<Integer, List<SysFrontMenu>> childrenMap = menus.stream()
                .filter(m -> m.getParentId() != 0)
                .collect(Collectors.groupingBy(SysFrontMenu::getParentId));
        menus.forEach(m -> m.setChildren(childrenMap.get(m.getId())));
        return menus.stream()
                .filter(m -> m.getParentId() == 0)
                .collect(Collectors.toList());
    }

    /**
     * 构建导航菜单树形结构
     */
    private List<FrontMenuVO> buildNavTree(List<SysFrontMenu> menus) {
        // 转换为 VO
        List<FrontMenuVO> voList = menus.stream().map(m -> {
            FrontMenuVO vo = new FrontMenuVO();
            vo.setId(m.getId());
            vo.setTitle(m.getTitle());
            vo.setPath(m.getPath());
            vo.setIcon(m.getIcon());
            vo.setSort(m.getSort());
            vo.setHidden(m.getHidden());
            vo.setIsExternal(m.getIsExternal());
            vo.setColorClass(m.getColorClass());
            return vo;
        }).collect(Collectors.toList());

        // 构建树形
        Map<Integer, List<FrontMenuVO>> childrenMap = voList.stream()
                .filter(v -> v.getId() != null)
                .collect(Collectors.groupingBy(v -> {
                    // 查找 parentId
                    return menus.stream()
                            .filter(m -> m.getId().equals(v.getId()))
                            .findFirst()
                            .map(SysFrontMenu::getParentId)
                            .orElse(0);
                }));
        voList.forEach(v -> v.setChildren(childrenMap.get(v.getId())));

        return voList.stream()
                .filter(v -> {
                    return menus.stream()
                            .filter(m -> m.getId().equals(v.getId()))
                            .findFirst()
                            .map(m -> m.getParentId() == 0)
                            .orElse(false);
                })
                .collect(Collectors.toList());
    }
}
```

#### 3.7.5 缓存注意事项

| 事项 | 说明 |
|------|------|
| **缓存穿透** | 前台菜单数据量小，且始终有数据（至少有一个「首页」菜单），不存在穿透风险 |
| **缓存雪崩** | 单键缓存，不存在批量过期问题。Redis 重启后首次请求会查库重建缓存 |
| **缓存一致性** | 增/删/改操作均使用 `@CacheEvict(allEntries = true)` 清除整个 `front_menu` 命名空间，确保数据一致 |
| **管理页面不缓存** | `getMenuTree()` 不加缓存注解，后台管理页面始终查询最新数据，保证编辑体验 |
| **`mojian-commom` 模块** | Service 实现类在 `mojian-commom` 中，`@Cacheable`/`@CacheEvict` 注解需要该模块支持 Spring Cache（已支持，`@EnableCaching` 在启动类中全局启用） |

```javascript
   * 从 store 读取菜单数据，转换为组件内部使用的格式
   */
  menuItems() {
    return (this.$store.state.frontMenuList || []).map(item => {
      const hasChildren = item.children && item.children.length > 0
      return {
        name: item.title,
        // 有子菜单时，一级项 path 取第一个子菜单的 path（保持原有行为）
        path: hasChildren ? item.children[0].path : item.path,

        colorClass: item.colorClass || '',
        isExternal: item.isExternal === 1,
        hidden: item.hidden === 1,
        children: hasChildren ? item.children.map(child => ({
          name: child.title,
          path: child.path,
          icon: child.icon || '',
          colorClass: child.colorClass || '',
          external: child.isExternal === 1,
        })) : null
      }
    })
  },
  /**
   * 过滤隐藏项，并处理有子菜单的一级项 path

  filteredMenuItems() {
    return this.menuItems
      .filter(item => !item.hidden)
      .map(item => ({

        path: item.children ? item.children[0].path : item.path
```

```javascript
    const rootRoute = this.$router.options.routes.find(route => route.path === '/')
    if (!rootRoute || !rootRoute.children) return []
    return rootRoute.children.filter(route => {
      if (!route.name || route.meta?.hidden) return false
      return true
    })
  }
}

// 修改后：从 store 中读取动态菜单数据
computed: {
  routes() {
    return (this.$store.state.frontMenuList || [])
      .filter(item => item.hidden !== 1)
      .map(item => {
        const hasChildren = item.children && item.children.length > 0
        return {
          // 有子菜单时取第一个子菜单的路径，外链保持原 URL
          path: (hasChildren && item.isExternal !== 1)
            ? item.children[0].path
            : item.path,
          meta: {
            icon: item.icon || '',
            title: item.title,
          },
          isExternal: item.isExternal === 1,
        }
      })
  }
}
```

##### 5b. 修改模板 — 外链菜单处理（L15–L25）

当前 MobileMenu 统一使用 `router-link`，外链菜单会导致路由错误。需要区分处理：

```html
<!-- 修改前 -->
<router-link v-for="route in routes" :key="route.path" :to="route.path"
  class="menu-item" :class="{ active: $route.path === route.path }"
  @click.native="closeMenu">
  <i v-if="route.meta?.icon" :class="route.meta.icon"></i>
  <span>{{ getMenuTitle(route) }}</span>
</router-link>

<!-- 修改后 -->
<template v-for="route in routes">
  <!-- 外链菜单 -->
  <a v-if="route.isExternal"
     :key="route.path"
     :href="route.path"
     target="_blank"
     rel="noopener noreferrer"
     class="menu-item"
     @click="closeMenu">
    <i v-if="route.meta.icon" :class="route.meta.icon"></i>
    <span>{{ route.meta.title }}</span>
  </a>
  <!-- 内部路由菜单 -->
  <router-link v-else
     :key="route.path"
     :to="route.path"
     class="menu-item"
     :class="{ active: $route.path === route.path }"
     @click.native="closeMenu">
    <i v-if="route.meta.icon" :class="route.meta.icon"></i>
    <span>{{ route.meta.title }}</span>
  </router-link>
</template>
```

##### 5c. `getMenuTitle` 方法简化（L71–L73）

当前逻辑从 `route.meta.title` 中截取 `" - "` 前的部分。改为动态菜单后，`title` 字段已经是纯菜单名（如「首页」而非「首页 - 拾壹博客」），因此可以简化：

```javascript
// 修改前
getMenuTitle(route) {
  return route.meta?.title?.split(' - ')[0] || route.name
}

// 修改后（简化，也可直接在模板中使用 route.meta.title）
getMenuTitle(route) {
  return route.meta?.title || ''
}
```


在 store action 的 catch 中使用：


### 10.4 「文章归档」一级菜单 path 特殊处理

当前 Header 中「文章归档」一级菜单的 `path` 为 `/archives`，但 `filteredMenuItems` 会将其覆盖为第一个子菜单「归档」的 path `/archive`。这个行为在改造后通过 `computed.filteredMenuItems` 中的 `item.children ? item.children[0].path : item.path` 保持一致。

### 10.5 MobileMenu 不展示子菜单

MobileMenu 组件当前只展示一级菜单，不支持下拉展开。改造后同样只渲染一级菜单项，有子菜单的项跳转到第一个子菜单的路径。如需未来支持子菜单展开，需额外改造 MobileMenu 组件。

### 10.6 获取菜单树接口不加权限校验

`GET /sys/frontMenu/tree` 接口不添加 `@SaCheckPermission`，与现有 `SysMenuController` 的 `/tree` 接口保持一致。

**原因**：项目通过 `StpInterfaceImpl` + `SysMenuMapper.xml` 的 `getPermissionList` 查询权限时，只查 `type='BUTTON'` 的记录。而菜单树查看是 `MENU` 类型，其 `perm` 字段不会被包含在权限列表中，导致 `NotPermissionException`。因此查看类接口只需登录即可访问，增删改接口通过 `BUTTON` 类型的权限标识进行控制。

### 13.5 前台渲染改造（blog-web）

改造 `filteredMenuItems` computed，直接使用数据库中的图标字段：

```javascript
computed: {
  filteredMenuItems() {
    const isDark = this.currentTheme === 'dark'
    return this.menuItems.map(item => {
      const processItem = (obj) => {
        const processed = { ...obj }
        // 根据主题使用对应的图标字段
        if (isDark && processed.iconDark) {
          processed.icon = processed.iconDark
        } else if (!isDark && processed.icon) {
          processed.icon = processed.icon
        }
        if (obj.children) {
          processed.children = obj.children.map(processItem)
        }
        return processed
      }
      return processItem(item)
    }).map(item => ({
      ...item,
      path: item.children ? item.children[0].path : item.path
    }))
  }
}
```
