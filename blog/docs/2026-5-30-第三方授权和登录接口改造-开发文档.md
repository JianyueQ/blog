# 第三方授权和登录接口改造 - 开发文档

> 日期：2026-05-30
> 
> 目标：对现有的第三方授权地址获取接口（`/api/auth/render/{source}`）和授权回调接口（`/api/auth/callback/{source}`）进行前后台差异化改造。
> 
> **核心策略**：
> - **前台用户（blog-web）**：保持现有逻辑不变 —— 授权回调后，若账户不存在则自动创建并登录
> - **后台管理员（blog-admin）**：严格校验 —— 必须先将第三方账号与已有管理员账户绑定，才能通过第三方登录后台；未绑定的第三方账号无法登录

---

## 一、现状分析

### 1.1 当前接口

| 接口 | 路径 | 说明 |
|------|------|------|
| 获取授权地址 | `GET /api/auth/render/{source}` | 根据 source 构建第三方授权跳转 URL |
| 授权回调 | `GET /api/auth/callback/{source}` | 第三方授权回调，获取用户信息后自动注册/登录 |

### 1.2 当前 `authLogin` 方法逻辑

```java
// AuthServiceImpl.authLogin() 当前逻辑（前台后台共用）
1. 通过 JustAuth 获取第三方用户信息（uuid、avatar 等）
2. 根据 uuid 查询 sys_user 表（username = uuid）
3. 如果用户不存在 → 自动创建 sys_user + 分配普通用户角色
4. 如果用户存在 → 直接登录
5. StpUtil.login(user.getId())
6. 重定向到 Constants.LOGIN_SUCCESS_URL + token
```

### 1.3 存在的问题

1. **前后台共用同一个回调接口**，无法区分来源（前台 blog-web 还是后台 blog-admin）
2. **后台安全隐患**：任何人都可以通过第三方登录自动创建账号并登录后台
3. **缺少绑定关系表**：`sys_user_third_party` 表已存在于数据库中但尚无对应 Java 代码（Entity / Mapper / Service），无法记录管理员与第三方账号的绑定关系
4. **回调地址固定**：`Constants.LOGIN_SUCCESS_URL` 硬编码为前台地址 `https://gp.jianyue.cloud/?token=`，不适用于后台

## 二、改造方案

### 2.1 双 OAuth 应用策略

由于第三方平台（GitHub / Gitee / QQ）**每个 OAuth 应用只能配置一个回调地址**，前后台需要各自一套 OAuth 应用：

- **前台应用**：`config_key` = `github` / `gitee` / `qq`，回调地址指向 `/api/auth/callback/{source}`
- **后台应用**：`config_key` = `github_admin` / `gitee_admin` / `qq_admin`，回调地址指向 `/api/auth/callback/admin/{source}`

在 `sys_third_party_config` 表中通过 `config_key` 后缀 `_admin` 区分前后台配置。

### 2.2 接口路径设计

| 场景 | 授权地址接口 | 回调接口 | config_key |
|------|-------------|---------|------------|
| 前台用户 | `GET /api/auth/render/{source}` | `GET /api/auth/callback/{source}` | `github` / `gitee` / `qq` |
| 后台管理员 | `GET /api/auth/render/{source}?sourceType=admin` | `GET /api/auth/callback/admin/{source}` | `github_admin` / `gitee_admin` / `qq_admin` |

> **说明**：
> - 授权地址接口通过 `sourceType` 查询参数传递来源标识，内部使用 `source + "_admin"` 作为 config_key 查询后台 OAuth 配置
> - 回调接口新增 `/api/auth/callback/admin/{source}` 路径专门处理后台回调，内部同样使用 `source + "_admin"` 查询配置
> - 所有路径以 `/api/` 开头，已被 Sa-Token 的 `excludePathPatterns("/api/**")` 放行

### 2.3 后台第三方登录流程

```
后台管理员操作流程：
1. 管理员先在后台"个人设置"页面，绑定第三方账号（如 GitHub）
   → 调用授权接口获取授权地址 → 跳转第三方授权 → 回调后将绑定关系写入 sys_user_third_party
2. 登录时，点击第三方登录图标 → 跳转授权 → 回调到 /api/auth/callback/admin/{source}
3. 后端校验：
   a. 获取第三方用户 uuid
   b. 查询 sys_user_third_party 表中是否存在 third_party_type + third_party_id 的绑定记录
   c. 存在绑定 → 根据 user_id 查询 sys_user → 执行 StpUtil.login() → 重定向到后台首页
   d. 不存在绑定 → 重定向回后台登录页，URL 携带错误信息（如 ?error=not_bound）
```

### 2.4 前台第三方登录流程（不变）

```
前台用户操作流程（保持现有逻辑）：
1. 点击第三方登录图标 → 跳转授权 → 回调到 /api/auth/callback/{source}
2. 后端处理：
   a. 获取第三方用户 uuid
   b. 查询 sys_user（username = uuid）
   c. 不存在 → 自动创建 sys_user + 分配普通用户角色
   d. 存在 → 直接登录
   e. StpUtil.login() → 重定向到前台首页
```

### 2.5 回调重定向地址

| 场景 | 登录成功重定向 | 登录失败重定向 |
|------|--------------|--------------|
| 前台 | `Constants.LOGIN_SUCCESS_URL + token`（现有） | `Constants.LOGIN_URL`（现有） |
| 后台 | `Constants.ADMIN_LOGIN_SUCCESS_URL + token`（新增常量） | `Constants.ADMIN_LOGIN_URL + "?error=not_bound"`（新增常量） |

需要在 `Constants.java` 中新增后台相关常量：

```java

// 后台登录成功重定向地址
public static final String ADMIN_LOGIN_SUCCESS_URL = "https://www.shiyit.com/admin/?token=";
```

> **注意**：以上域名需根据实际部署环境调整。

#### 3.3.2 实现类

**文件**：`mojian-commom/src/main/java/com/mojian/service/impl/SysUserThirdPartyServiceImpl.java`

```java
@Service
@RequiredArgsConstructor
public class SysUserThirdPartyServiceImpl extends ServiceImpl<SysUserThirdPartyMapper, SysUserThirdParty>
        implements SysUserThirdPartyService {

    @Override
    public SysUserThirdParty getByThirdParty(String thirdPartyType, String thirdPartyId) {
        return baseMapper.selectOne(new LambdaQueryWrapper<SysUserThirdParty>()
                .eq(SysUserThirdParty::getThirdPartyType, thirdPartyType)
                .eq(SysUserThirdParty::getThirdPartyId, thirdPartyId));
    }

    @Override
    public List<SysUserThirdParty> listByUserId(Integer userId) {
        return list(new LambdaQueryWrapper<SysUserThirdParty>()
                .eq(SysUserThirdParty::getUserId, userId));
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean bind(Integer userId, String thirdPartyType, String thirdPartyId,
                        String thirdPartyNickname, String thirdPartyAvatar) {
        // 检查是否已绑定
        SysUserThirdParty existing = getByThirdParty(thirdPartyType, thirdPartyId);
        if (existing != null) {
            throw new ServiceException("该第三方账号已被其他用户绑定");
        }
        // 检查当前用户是否已绑定该类型
        SysUserThirdParty userBound = baseMapper.selectOne(new LambdaQueryWrapper<SysUserThirdParty>()
                .eq(SysUserThirdParty::getUserId, userId)
                .eq(SysUserThirdParty::getThirdPartyType, thirdPartyType));
        if (userBound != null) {
            throw new ServiceException("您已绑定" + thirdPartyType + "账号，请先解绑再重新绑定");
        }

        SysUserThirdParty binding = SysUserThirdParty.builder()
                .userId(userId)
                .thirdPartyType(thirdPartyType)
                .thirdPartyId(thirdPartyId)
                .thirdPartyNickname(thirdPartyNickname)
                .thirdPartyAvatar(thirdPartyAvatar)
                .build();
        return save(binding);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean unbind(Integer userId, String thirdPartyType) {
        return remove(new LambdaQueryWrapper<SysUserThirdParty>()
                .eq(SysUserThirdParty::getUserId, userId)
                .eq(SysUserThirdParty::getThirdPartyType, thirdPartyType));
    }
}
```

#### 3.7.3 新增 adminAuthLogin 方法

```java
@Override
public void adminAuthLogin(AuthCallback callback, String source, HttpServletResponse httpServletResponse) throws IOException {
    // 后台场景使用 source + "_admin" 作为 config_key 获取后台 OAuth 配置
    String configKey = source + "_admin";
    AuthRequest authRequest = getAuthRequest(configKey);
    AuthResponse<AuthUser> response = authRequest.login(callback);

    if (response.getData() == null) {
        log.info("管理员取消了 {} 第三方登录", source);
        httpServletResponse.sendRedirect(Constants.ADMIN_LOGIN_URL);
        return;
    }

    String result = JSONObject.toJSONString(response.getData());
    log.info("后台第三方登录验证结果:{}", result);

    JSONObject jsonObject = JSON.parseObject(result);
    String uuid = jsonObject.get("uuid").toString();

    // 查询绑定关系
    SysUserThirdParty binding = sysUserThirdPartyService.getByThirdParty(source, uuid);
    if (binding == null) {
        log.info("第三方账号未绑定后台用户，type={}, uuid={}", source, uuid);
        httpServletResponse.sendRedirect(Constants.ADMIN_LOGIN_URL + "?error=not_bound");
        return;
    }

    // 根据绑定的 user_id 查询用户
    SysUser user = userMapper.selectById(binding.getUserId());
    if (user == null) {
        log.warn("绑定的用户不存在，userId={}", binding.getUserId());
        httpServletResponse.sendRedirect(Constants.ADMIN_LOGIN_URL + "?error=user_not_found");
        return;
    }

    // 校验用户状态
    if (user.getStatus() != Constants.YES) {
        httpServletResponse.sendRedirect(Constants.ADMIN_LOGIN_URL + "?error=disabled");
        return;
    }

    StpUtil.login(user.getId());
    httpServletResponse.sendRedirect(Constants.ADMIN_LOGIN_SUCCESS_URL + StpUtil.getTokenValue());
}
```

```typescript
const handleCallbackToken = () => {
  const url = new URL(window.location.href);
  
  // 处理绑定/登录失败
  const error = url.searchParams.get('error');
  if (error) {
    const errorMessages: Record<string, string> = {
      'not_bound': '该第三方账号未绑定后台账户，请先使用账号密码登录后在个人设置中绑定',
      'user_not_found': '绑定的用户不存在',
      'disabled': '账号已被禁用，请联系管理员',
    };
    ElMessage.error(errorMessages[error] || '登录失败');
    url.searchParams.delete('error');
    window.history.replaceState({}, '', url.toString());
    return;
  }

  // 处理登录成功
  const token = url.searchParams.get('token');
  if (token) {
    setToken(token);
    url.searchParams.delete('token');
    window.history.replaceState({}, '', url.toString());
    router.push('/');
    ElMessage.success('第三方登录成功');
  }
};
```

## 八、注意事项

1. **state 参数安全**：JustAuth 的 `AuthStateUtils.createState()` 生成的 state 用于防 CSRF，在前面加 `admin_` 前缀后，回调时需要验证 state 格式。可考虑使用更安全的编码方式（如 Base64 编码 JSON）
2. **回调路径放行**：新增的 `/api/auth/callback/admin/{source}` 路径以 `/api/` 开头，已被 Sa-Token 拦截器放行，无需额外配置
3. **绑定唯一性**：一个第三方账号只能绑定一个后台用户，一个后台用户同类型只能绑定一个第三方账号
4. **后台常量地址**：`ADMIN_LOGIN_URL` 和 `ADMIN_LOGIN_SUCCESS_URL` 需要根据实际部署域名配置，建议后续迁移到 `sys_config` 表或 `application.yml` 中管理
5. **前后台独立 OAuth 应用**：每个第三方平台需要创建两个 OAuth 应用（前台 + 后台），在 `sys_third_party_config` 表中分别存储，后台配置的 `config_key` 使用 `_admin` 后缀
6. **`sys_user_third_party` 表已存在**：无需执行建表 SQL，仅需创建对应的 Java 代码
7. **已有第三方登录用户迁移**：当前 `sys_user` 表中通过第三方登录创建的用户（`username` = uuid），如果需要在后台也能用第三方登录，需要手动在 `sys_user_third_party` 表中补充绑定记录
8. **后台 OAuth 应用配置**：需要在 GitHub / Gitee / QQ 开放平台分别创建后台 OAuth 应用，回调地址填写对应的 `/api/auth/callback/admin/{source}` 路径，获取到 Client ID 和 Secret 后填入 `sys_third_party_config` 表中后台配置记录，并启用（status=1）
