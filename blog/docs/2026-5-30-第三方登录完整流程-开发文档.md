# 第三方登录完整流程 - 开发文档

> 日期：2026-05-30
>
> 本文档整合了第三方登录功能从配置管理、授权、绑定到登录的完整流程，涵盖前后台差异化策略、账号绑定机制、缓存优化等核心设计。

---

## 一、系统概览

### 1.1 功能模块

| 模块 | 说明 |
|------|------|
| **配置管理** | 后台管理页面维护第三方登录配置（appId、appSecret、回调地址、状态等），支持前台/后台配置切换 |
| **授权流程** | 用户点击第三方登录图标 → 获取 OAuth 授权地址 → 跳转第三方平台授权 |
| **账号绑定** | 管理员在个人中心将第三方账号与系统账户绑定，支持绑定/解绑操作 |
| **登录流程** | 授权回调后，前台自动注册/登录，后台严格校验绑定关系 |

### 1.2 前后台差异化策略

| 维度 | 前台（blog-web） | 后台（blog-admin） |
|------|-----------------|-------------------|
| 登录策略 | 宽松：授权后自动注册/登录 | 严格：必须预先绑定才能登录 |
| config_key | `github` / `gitee` / `qq` | `github_admin` / `gitee_admin` / `qq_admin` |
| config_source | `front` | `admin` |
| 回调路径 | `/api/auth/callback/{source}` | `/api/auth/callback/admin/{source}` |
| OAuth 应用 | 前台 OAuth 应用 | 后台 OAuth 应用（独立的 Client ID / Secret） |

> **为什么需要两套 OAuth 应用？** 第三方平台每个 OAuth 应用只能配置一个回调地址，前后台回调路径不同，因此需要各自一套。

### 1.3 技术选型

| 技术 | 用途 |
|------|------|
| **JustAuth 1.16.7** | 第三方 OAuth 授权集成（支持 Gitee / GitHub / QQ） |
| **Sa-Token** | 用户认证与会话管理 |
| **Spring Cache + Redis** | 第三方配置数据缓存 |
| **MyBatis-Plus** | 数据库操作 |
| **Element Plus** | 后台管理 UI 组件 |
| **BroadcastChannel API** | 跨窗口通信（绑定结果通知） |

## 四、OAuth 授权流程

### 4.1 获取授权地址

**接口**：`GET /api/auth/render/{source}?sourceType=admin&purpose=bind`

| 参数 | 类型 | 说明 |
|------|------|------|
| `source` | path | 第三方类型：github / gitee / qq |
| `sourceType` | query（可选） | 来源类型：空=前台，`admin`=后台 |
| `purpose` | query（可选） | 用途：空=登录，`bind`=绑定 |

**核心逻辑**（`AuthServiceImpl.renderAuth`）：

```java
public String renderAuth(String source, String sourceType, String purpose) {
    // 后台场景使用 source + "_admin" 作为 config_key
    String configKey = "admin".equals(sourceType) ? source + "_admin" : source;
    AuthRequest authRequest = getAuthRequest(configKey);
    String state = AuthStateUtils.createState();
    if ("bind".equals(purpose)) {
        // 绑定场景：将当前用户ID编码到 state 中
        Integer userId = StpUtil.getLoginIdAsInt();
        state = "bind_" + userId + "_" + state;
    } else if ("admin".equals(sourceType)) {
        state = "admin_" + state;
    }
    return authRequest.authorize(state);
}
```

**state 编码规则**：

| 场景 | state 格式 | 示例 |
|------|-----------|------|
| 前台登录 | `{randomState}` | `a1b2c3d4e5` |
| 后台登录 | `admin_{randomState}` | `admin_a1b2c3d4e5` |
| 账号绑定 | `bind_{userId}_{randomState}` | `bind_1_a1b2c3d4e5` |

### 4.2 构建 AuthRequest

使用 JustAuth Builder 模式构建 `AuthConfig`：

```java
AuthConfig authConfig = AuthConfig.builder()
        .clientId(config.getAppId())
        .clientSecret(config.getAppSecret())
        .redirectUri(config.getRedirectUrl())
        .build();

return switch (source) {
    case "gitee" -> new AuthGiteeRequest(authConfig);
    case "github" -> new AuthGithubRequest(authConfig);
    case "qq" -> new AuthQqRequest(authConfig);
    default -> null;
};
```

> **注意**：`AuthConfig` 的 `setClientId()` 等方法返回 `void`，不能使用链式调用，必须使用 Builder 模式。

### 5.2 为什么用 state 传 userId

OAuth 回调是**浏览器 302 重定向**，不是 AJAX 请求。Sa-Token 的 `token-name` 配置为 `Authorization`，前端将 token 存储在 `Neat-Admin-Token` cookie 中：

- 浏览器重定向**不会**自动携带 `Authorization` header
- `Neat-Admin-Token` cookie 名与 Sa-Token 期望的 `Authorization` cookie 名**不匹配**
- 因此 `StpUtil.getLoginIdAsInt()` 在回调中**无法获取当前登录用户**

**解决方案**：将 userId 编码到 OAuth state 参数中，回调时从 state 提取。state 由第三方平台原样返回，可靠且无需依赖 session。

### 5.3 后端回调处理

`AuthServiceImpl.adminAuthLogin` 通过检测 state 前缀分流：

```java
public void adminAuthLogin(AuthCallback callback, String source, HttpServletResponse response) {
    // 检测是否为绑定流程
    if (callback.getState() != null && callback.getState().startsWith("bind_")) {
        handleAdminBind(callback, source, response);
        return;
    }
    // 否则走后台登录流程...
}
```

`handleAdminBind` 私有方法处理绑定逻辑：

```java
private void handleAdminBind(AuthCallback callback, String source, HttpServletResponse response) {
    // 1. 通过 JustAuth 获取第三方用户信息
    AuthResponse<AuthUser> response = authRequest.login(callback);

    // 2. 从 state 中提取用户ID: bind_{userId}_{randomState}
    String[] parts = state.split("_", 3);
    Integer userId = Integer.parseInt(parts[1]);

    // 3. 提取第三方用户信息
    String uuid = jsonObject.get("uuid").toString();
    String nickname = ...;
    String avatar = ...;

    // 4. 执行绑定
    sysUserThirdPartyService.bind(userId, source, uuid, nickname, avatar);

    // 5. 重定向到前端绑定结果页面
    response.sendRedirect(Constants.ADMIN_BIND_SUCCESS_URL);
}
```

### 5.4 前端绑定交互

**个人中心页面**（`blog-admin/src/views/system/user/profile/index.vue`）：

```typescript
const handleBind = async (item: any) => {
  // 获取授权地址，purpose=bind 标识绑定流程
  const res = await getAuthRenderUrlApi(item.source, 'admin', 'bind')
  // 打开新窗口
  const authWindow = window.open(res.data, '_blank', 'width=800,height=600')

  // 通过 BroadcastChannel 监听绑定结果
  const channel = new BroadcastChannel('third_party_bind')
  channel.onmessage = (event) => {
    channel.close()
    if (event.data.success) {
      ElMessage.success('绑定成功')
    } else {
      ElMessage.error(event.data.msg || '绑定失败')
    }
    getThirdPartyList() // 刷新绑定列表
  }

  // 窗口关闭检测（用户手动关闭未授权）
  const checkClosed = setInterval(() => {
    if (authWindow?.closed) {
      clearInterval(checkClosed)
      channel.close()
    }
  }, 500)
}
```

## 六、第三方登录流程

### 6.1 前台登录流程（blog-web）

```
用户点击第三方登录图标
  → window.location.href = 授权URL
  → 第三方平台授权
  → 回调 GET /api/auth/callback/{source}?code=xxx&state=xxx
  → AuthServiceImpl.authLogin():
      1. JustAuth 获取第三方用户信息（uuid）
      2. 查询 sys_user（username = uuid）
      3. 不存在 → 自动创建用户 + 分配普通角色
      4. StpUtil.login(user.id)
      5. 重定向到 https://gp.jianyue.cloud/?token=xxx
  → 前台登录页 handleCallbackToken():
      1. 从 URL 提取 token
      2. setToken(token) 保存到 Cookie
      3. router.push('/') 跳转到首页
```

### 6.2 后台登录流程（blog-admin）

```
管理员点击第三方登录图标
  → window.location.href = 授权URL（sourceType=admin）
  → 第三方平台授权
  → 回调 GET /api/auth/callback/admin/{source}?code=xxx&state=admin_xxx
  → AuthServiceImpl.adminAuthLogin():
      1. JustAuth 获取第三方用户信息（uuid）
      2. 查询 sys_user_third_party（type + uuid）
      3. 未找到绑定 → 重定向 /admin/login?error=not_bound
      4. 找到绑定 → 查询 sys_user(user_id)
      5. 校验用户状态
      6. StpUtil.login(user.id)
      7. 重定向到 https://gp.jianyue.cloud/admin/?token=xxx
  → 后台登录页 handleCallbackToken():
      1. 从 URL 提取 token
      2. setToken(token) 保存到 Cookie
      3. router.push('/') → 路由 redirect 函数检测 token → 跳转 /login?token=xxx
      4. 登录页处理 token → 跳转 /dashboard
```

### 6.3 后台登录回调 Token 处理

**关键问题**：OAuth 回调重定向到 `https://gp.jianyue.cloud/admin/?token=xxx`，Vue Router 匹配 `/` 路径。

**根路由 redirect 函数**（`router/index.ts`）：

```typescript
{
  path: "/",
  component: Layout,
  redirect: (to) => {
    // 第三方登录回调携带 token 时，跳转到登录页处理
    if (to.query.token) {
      return { path: '/login', query: { token: to.query.token } }
    }
    return '/dashboard'
  },
  children: [...]
}
```

> **踩坑记录**：如果根路由直接 `redirect: "/dashboard"`，token 参数会被丢弃，登录页的 `handleCallbackToken()` 不会执行，导致用户被重定向回登录页。必须检测 token 参数并转发到登录页处理。

### 6.4 登录错误处理

后台登录页 `handleCallbackToken` 处理回调错误：

```typescript
const errorMessages: Record<string, string> = {
  'not_bound': '该第三方账号未绑定后台账户，请先使用账号密码登录后在个人设置中绑定',
  'user_not_found': '绑定的用户不存在',
  'disabled': '账号已被禁用，请联系管理员',
```

## 十、关键设计决策与踩坑记录

### 10.1 AuthConfig 必须用 Builder 模式

JustAuth 1.16.7 的 `AuthConfig.setClientId()` 等方法返回 `void`，不支持链式调用：

```java
// ❌ 错误：编译报错 "无法调用 void 类型的方法"
new AuthConfig().setClientId(id).setClientSecret(secret)

// ✅ 正确：使用 Builder 模式
AuthConfig.builder().clientId(id).clientSecret(secret).redirectUri(uri).build()
```

### 10.2 JustAuth login() 返回 AuthResponse 而非 AuthUser

```java
// ❌ 错误：类型不匹配
AuthUser user = authRequest.login(callback);

// ✅ 正确：从 AuthResponse 中提取
AuthResponse response = authRequest.login(callback);
if (!response.ok() || response.getData() == null) { /* 处理失败 */ }
AuthUser user = (AuthUser) response.getData();
```

### 10.3 mojian-commom 模块需显式引入 JustAuth 依赖

JustAuth 依赖最初只在 `mojian-auth` 模块中，`SysUserThirdPartyServiceImpl`（在 `mojian-commom` 中）引用 JustAuth 类会编译失败。需要在 `mojian-commom/pom.xml` 中显式添加：

```xml
<dependency>
    <groupId>me.zhyd.oauth</groupId>
    <artifactId>JustAuth</artifactId>
    <version>1.16.7</version>
</dependency>
```

### 10.4 OAuth 绑定回调中无法获取 Sa-Token 会话

OAuth 回调是浏览器 302 重定向，不携带 `Authorization` header，且前端 token 存储在 `Neat-Admin-Token` cookie（非 Sa-Token 期望的 `Authorization` cookie），导致 `StpUtil.getLoginIdAsInt()` 失败。

**解决方案**：将 userId 编码到 state 参数（`bind_{userId}_{state}`），回调时从 state 提取。

### 10.5 根路由 redirect 导致 token 丢失

OAuth 登录成功重定向到 `https://gp.jianyue.cloud/admin/?token=xxx`，如果根路由静态配置 `redirect: "/dashboard"`，token 参数被丢弃，登录页的 `handleCallbackToken()` 不会执行。

**解决方案**：根路由使用动态 redirect 函数，检测 `to.query.token` 存在时转发到 `/login?token=xxx`。

### 10.6 configKey 避免重复拼接 _admin 后缀

前端传入的 `configKey` 可能已包含 `_admin` 后缀（如从配置管理页面获取），后端不应再拼接一次。前端需做 `.replace(/_admin$/, '')` 处理。
