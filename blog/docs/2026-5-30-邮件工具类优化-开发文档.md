# 邮件工具类优化 - 开发文档

> 日期：2026-05-30
>
> 目标：将 `EmailUtil` 中的 SMTP 配置、邮件主题、邮件模板从 `application.yml` 和硬编码迁移至数据库（`sys_config` 表），通过 Redis 缓存（过期 1 天）减少数据库查询，并增加每人每日发送次数限制。

## 三、缓存设计

### 3.1 Redis 缓存键名

| 键名 | 值类型 | 过期时间 | 说明 |
|------|--------|---------|------|
| `email:config` | JSON String | 1 天 (86400s) | 缓存所有邮件相关配置（SMTP + 主题 + 模板） |
| `email:send_count:{email}` | Integer | 1 天 (86400s) | 某邮箱当日已发送次数 |

### 3.2 Constants / RedisConstants 新增常量

**`Constants.java` 新增 Spring Cache 缓存名常量：**

```java
/**
 * 系统参数配置缓存名
 */
public static final String CACHE_SYS_CONFIG = "sys_config";
```

> 注意：现有 `SysConfigServiceImpl` 中 `@Cacheable(cacheNames = "sys_config")` 和 `@CachePut(cacheNames = "sys_config")` 使用了硬编码字符串，
> 本次改造需一并替换为 `Constants.CACHE_SYS_CONFIG`，保持与 `CACHE_FRONT_MENU`、`CACHE_THIRD_PARTY_CONFIG` 等已有常量一致的规范。

**`RedisConstants.java` 新增 Redis 键名常量：**

```java
/**
 * 邮件配置缓存 Key
 */
public static final String EMAIL_CONFIG_KEY = "email:config";

/**
 * 邮件发送次数 Key（后缀为邮箱地址）
 */
public static final String EMAIL_SEND_COUNT_KEY = "email:send_count:";
```

### 3.3 缓存结构

`email:config` 存储一个 JSON 对象，包含所有邮件配置项：

```json
{
  "smtpHost": "smtp.qq.com",
  "smtpPort": 465,
  "smtpEmail": "3137390391@qq.com",
  "smtpPassword": "glcuxbeffeeldcje",
  "mailSubject": "您有一封来自 {siteName} 的回执！",
  "mailTemplate": "<html>...</html>"
}
```

### 3.4 缓存读写流程

```
发送验证码请求
    │
    ▼
Redis 查 email:config ──命中──▶ 直接使用缓存配置
    │
    未命中
    │
    ▼
从 sys_config 表批量查询 mail_* 配置
    │
    ▼
组装 EmailConfigVO 对象
    │
    ▼
写入 Redis（TTL = 1天）
    │
    ▼
使用配置构建 JavaMailSender 并发送
```

### 3.5 缓存失效

当管理员在后台修改 `sys_config` 表中 `config_key` 以 `mail_` 开头的配置时，需清除 `email:config` 缓存。在 `SysConfigServiceImpl.update()` 中增加清除逻辑：

```java
@Override
@CachePut(cacheNames = Constants.CACHE_SYS_CONFIG, key = "#sysConfig.configKey")
public SysConfig update(SysConfig sysConfig) {
    // ... 原有逻辑 ...
    // 如果是邮件相关配置，清除邮件缓存
    if (sysConfig.getConfigKey().startsWith("mail_")) {
        redisUtil.delete(RedisConstants.EMAIL_CONFIG_KEY);
    }
    return sysConfig;
}
```

同时需将 `selectConfigByKey()` 的注解一并替换：

```java
@Cacheable(cacheNames = Constants.CACHE_SYS_CONFIG, key = "#key")
public SysConfig selectConfigByKey(String key) { ... }
```

## 四、发送频率限制

### 4.1 限流规则

| 规则 | 限制值 | 说明 |
|------|--------|------|
| 同一邮箱每日发送上限 | 5 次/天 | 防止对单个邮箱恶意轰炸 |
| 同一邮箱发送间隔 | 60 秒 | 防止短时间重复发送（复用已有的验证码过期机制） |

### 4.2 实现方式

使用 Redis 计数器实现：

```
发送前检查:
    1. 检查 email:send_count:{email} 是否存在
       ├── 存在 且 count >= 5 → 拒绝："今日发送次数已达上限，请明天再试"
       └── 不存在 或 count < 5 → 允许发送

发送成功后:
    1. 如果 email:send_count:{email} 不存在
       → set(key, 1, 86400, SECONDS)  // 首次发送，设置计数1，过期1天
    2. 如果已存在
       → increment(key, 1)            // 计数+1
```

### 4.3 接口层防护

在 `AuthController.sendEmailCode()` 或 `AuthServiceImpl.sendEmailCode()` 中增加校验逻辑：

```java
public Boolean sendEmailCode(String email) throws MessagingException {
    // 1. 检查发送频率
    String countKey = RedisConstants.EMAIL_SEND_COUNT_KEY + email;
    Object count = redisUtil.get(countKey);
    if (count != null && Integer.parseInt(count.toString()) >= 5) {
        throw new ServiceException("今日发送次数已达上限，请明天再试");
    }

    // 2. 检查验证码是否仍然有效（防止重复发送）
    if (redisUtil.hasKey(RedisConstants.CAPTCHA_CODE_KEY + email)) {
        throw new ServiceException("验证码尚未过期，请稍后再试");
    }

    // 3. 发送邮件
    emailUtil.sendCode(email);

    // 4. 递增发送计数
    if (count == null) {
        redisUtil.set(countKey, 1, RedisConstants.DAY_EXPIRE, TimeUnit.SECONDS);
    } else {
        redisUtil.increment(countKey, 1);
    }

    return true;
}
```

### 5.1 新增 VO：EmailConfigVO

```java
    private Integer smtpPort;
    private String smtpEmail;
    private String smtpPassword;
    private String mailSubject;
    private String mailTemplate;
}
```

### 5.2 改造 EmailUtil.java

**改造要点：**

1. 移除 `@Value` 注入的 SMTP 配置字段
2. 新增 `SysConfigService` 依赖，用于从数据库读取配置
3. 新增 `SysWebConfigMapper` 依赖，用于获取站点信息（名称、Logo、URL）
4. 新增 `getEmailConfig()` 方法：先查 Redis 缓存，未命中则查数据库并回写缓存
5. 新增 `buildMailSender(EmailConfigVO)` 方法：根据配置构建 `JavaMailSenderImpl`（仅在缓存未命中时重建）
6. 改造 `sendCode()` 方法：从缓存读取模板，替换占位符后发送
7. 改造 `send()` 方法：主题从配置读取，替换占位符

**改造后的核心方法伪代码：**

```java
@Component
@RequiredArgsConstructor
public class EmailUtil {

    private final RedisUtil redisUtil;
    private final SysConfigMapper sysConfigMapper;
    private final SysWebConfigMapper sysWebConfigMapper;

    private JavaMailSenderImpl javaMailSender;
    private EmailConfigVO cachedConfig;

    /**
     * 获取邮件配置（优先缓存）
     */
    private EmailConfigVO getEmailConfig() {
        Object value = redisUtil.get(RedisConstants.EMAIL_CONFIG_KEY);
        if (value != null) {
            return JSONObject.parseObject(value.toString(), EmailConfigVO.class);
        }
        // 从数据库批量查询
        List<SysConfig> configs = sysConfigMapper.selectList(
            new LambdaQueryWrapper<SysConfig>()
                .likeRight(SysConfig::getConfigKey, "mail_")
        );
        EmailConfigVO config = buildConfigVO(configs);
        redisUtil.set(RedisConstants.EMAIL_CONFIG_KEY,
            JSONObject.toJSONString(config),
            RedisConstants.DAY_EXPIRE, TimeUnit.SECONDS);
        return config;
    }

    /**
     * 构建或复用 JavaMailSender
     */
    private JavaMailSenderImpl getMailSender(EmailConfigVO config) {
        if (javaMailSender != null && config.equals(cachedConfig)) {
            return javaMailSender;
        }
        javaMailSender = new JavaMailSenderImpl();
        javaMailSender.setHost(config.getSmtpHost());
        javaMailSender.setPort(config.getSmtpPort());
        javaMailSender.setUsername(config.getSmtpEmail());
        javaMailSender.setPassword(config.getSmtpPassword());
        javaMailSender.setDefaultEncoding("UTF-8");
        Properties p = new Properties();
        p.setProperty("mail.smtp.auth", "true");
        p.setProperty("mail.smtp.ssl.enable", "true");
        javaMailSender.setJavaMailProperties(p);
        cachedConfig = config;
        return javaMailSender;
    }

    /**
     * 发送验证码
     */
    public void sendCode(String email) throws MessagingException {
        EmailConfigVO config = getEmailConfig();
        JavaMailSenderImpl sender = getMailSender(config);

        int code = generateCode();
        String siteInfo = getSiteInfo();  // 从 sys_web_config 获取站点信息

        // 替换模板占位符
        String content = config.getMailTemplate()
            .replace("{code}", String.valueOf(code))
            .replace("{siteName}", siteInfo.getName())
            .replace("{siteLogo}", siteInfo.getLogo())
            .replace("{siteUrl}", siteInfo.getWebUrl());

        // 替换主题占位符
        String subject = config.getMailSubject()
            .replace("{siteName}", siteInfo.getName());

        this.send(sender, email, content, subject);

        // 存储验证码
        redisUtil.set(RedisConstants.CAPTCHA_CODE_KEY + email, code + "");
        redisUtil.expire(RedisConstants.CAPTCHA_CODE_KEY + email,
            RedisConstants.MINUTE_EXPIRE, TimeUnit.SECONDS);
    }
}
```

## 六、后台管理界面

## 八、验证标准

| # | 验证项 | 预期结果 |
|---|--------|---------|
| 1 | 首次发送验证码 | 从数据库加载配置，写入 Redis，邮件成功发送 |
| 2 | 第二次发送验证码（不同邮箱） | 从 Redis 读取缓存配置，不查数据库 |
| 3 | 同一邮箱发送第 6 次 | 返回错误："今日发送次数已达上限" |
| 4 | 验证码未过期时再次发送 | 返回错误："验证码尚未过期，请稍后再试" |
| 5 | 后台修改邮件主题后发送 | 使用新主题发送，Redis 缓存已刷新 |
| 6 | 后台修改 SMTP 密码后发送 | 使用新密码连接 SMTP 服务器 |
| 7 | Redis 缓存过期后发送 | 重新从数据库加载配置 |
