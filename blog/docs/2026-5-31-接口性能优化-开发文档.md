## 二、已实施的优化方案

### 2.1 WebConfig 缓存写回（问题 #1 + #5）

**文件**：`mojian-api/.../service/impl/HomeServiceImpl.java`

**问题**：`getWebConfig()` 检查 Redis 缓存存在时从 Redis 读取，但缓存为空时只查 DB 却**从未写回缓存**，导致每次请求都直接查数据库。同时 `hasKey` + `get` 产生两次 Redis 网络往返。

**修复**：
1. DB 查询后写回 Redis，过期时间 7 天
2. 用 `get` 判空替代 `hasKey` + `get`，减少一次 Redis 往返

```java
// 修复后
if (value == null) {
    sysWebConfig = sysWebConfigMapper.selectOne(wrapper);
    if (sysWebConfig != null) {
        redisUtil.set(RedisConstants.WEB_CONFIG_KEY,
                JSONObject.toJSONString(sysWebConfig),
                RedisConstants.WEEK_EXPIRE, TimeUnit.SECONDS);
    }
} else {
    sysWebConfig = JSONObject.parseObject(value.toString(), SysWebConfig.class);
}

// Redis 读取优化
Object viewsObj = redisUtil.get(RedisConstants.BLOG_VIEWS_COUNT);
if (viewsObj != null) {
    blogViewsCount = Long.parseLong(viewsObj.toString());
}
```

**预期效果**：`/api/webConfig` 从 ~865ms 降至 ~50ms（缓存命中时）

### 2.2 文章列表标签 N+1 修复（问题 #2）

**文件**：
- `mojian-api/.../service/impl/ArticleServiceImpl.java`
- `mojian-commom/.../mapper/SysTagMapper.java`
- `mojian-server/.../mapper/SysTagMapper.xml`
- `mojian-commom/.../vo/tag/TagListVo.java`

**问题**：`articleResultMap` 中使用嵌套 `select` 查询标签，分页返回 10 条文章会产生 10 次额外 SQL 查询。

**修复**：在 Service 层批量查询所有文章的标签，然后在内存中关联：

```java
IPage<ArticleListVo> page = sysArticleMapper.getArticleListApi(...);
List<Long> articleIds = records.stream().map(ArticleListVo::getId).collect(toList());
List<TagListVo> allTags = sysTagMapper.getTagsByArticleIds(articleIds); // 1次查询
Map<Long, List<TagListVo>> tagMap = allTags.stream()
        .collect(groupingBy(TagListVo::getArticleId));
records.forEach(a -> a.setTags(tagMap.getOrDefault(a.getId(), emptyList())));
```

**新增 SQL**：`getTagsByArticleIds` 使用 `INNER JOIN` 一次查出所有文章的标签。

**预期效果**：`/api/article/list` 从 10+ 次 SQL 降至 2 次（主查询 + 标签批量查询）

### 2.3 评论子评论 N+1 修复（问题 #3）

**文件**：
- `mojian-api/.../service/impl/CommentServiceImpl.java`
- `mojian-commom/.../mapper/SysCommentMapper.java`
- `mojian-server/.../mapper/SysCommentMapper.xml`

**问题**：获取评论列表时，对每条父评论单独查子评论，10 条父评论 = 10 次额外 SQL。

**修复**：一次查出当前页所有父评论的子评论，内存中按 `parentId` 分组：

```java
List<Integer> parentIds = records.stream().map(CommentListVo::getId).collect(toList());
List<CommentListVo> allChildren = sysCommentMapper.getChildrenCommentsByParentIds(parentIds);
Map<Integer, List<CommentListVo>> childrenMap = allChildren.stream()
        .collect(groupingBy(CommentListVo::getParentId));
```

**新增方法**：`getChildrenCommentsByParentIds(List<Integer> parentIds)` — 使用 `IN` 查询。

**预期效果**：评论列表从 10+ 次 SQL 降至 2 次

### 2.5 热搜接口缓存（问题 #11）

**文件**：`mojian-api/.../service/impl/HomeServiceImpl.java`

**问题**：每次请求都同步调用外部 HTTP API（`coderutil.com`），外部服务响应慢时直接阻塞用户请求。

**修复**：增加 Redis 缓存，过期时间 30 分钟：

```java
String cacheKey = RedisConstants.HOT_SEARCH_KEY + type;
Object cached = redisUtil.get(cacheKey);
if (cached != null) return JSONObject.parseObject(cached.toString());
// ... 外部 HTTP 调用 ...
redisUtil.set(cacheKey, result, RedisConstants.HALF_HOUR_EXPIRE, TimeUnit.SECONDS);
```

**预期效果**：缓存命中时从 ~1,259ms 降至 ~50ms

### 2.6 标签/分类/友链列表缓存（问题 #10）

**文件**：
- `mojian-api/.../service/impl/TagServiceImpl.java` — 标签列表缓存
- `mojian-api/.../service/impl/ArticleServiceImpl.java` — 分类列表、分类文章缓存
- `mojian-api/.../service/impl/FriendServiceImpl.java` — 友链列表缓存

**缓存策略**：
| 缓存 Key | 过期时间 | 说明 |
|----------|---------|------|
| `tag:list` | 1天 | 标签列表 |
| `category:list` | 1天 | 全部分类 |
| `category:article_count` | 1天 | 分类+文章列表 |
| `friend:list` | 1天 | 友链列表 |

**缓存清除**：在对应的 Admin Service 中添加了缓存清除逻辑：
- `SysTagServiceImpl` — insert/update/delete 时清除 `tag:list`
- `SysCategoryServiceImpl` — insert/update/delete 时清除 `category:list` 和 `category:article_count`
- `SysFriendServiceImpl` — update 时清除 `friend:list`
- `SysArticleServiceImpl` — add/update/delete 时清除 `category:article_count`

### 2.7 文章归档优化（问题 #9）

**文件**：
- `mojian-api/.../service/impl/ArticleServiceImpl.java`
- `mojian-commom/.../mapper/SysArticleMapper.java`
- `mojian-server/.../mapper/SysArticleMapper.xml`

**问题**：先查所有年份，再对每年执行一次查询（N+1 模式），且 `DATE_FORMAT(create_time, '%Y')` 无法使用索引。

**修复**：一次查出所有已发布文章（仅查 id/title/createTime），在内存中按年份分组：

```java
List<ArticleListVo> allArticles = sysArticleMapper.getAllPublishedArticlesForArchive();
Map<Integer, List<ArticleListVo>> grouped = allArticles.stream()
        .collect(groupingBy(a -> a.getCreateTime().getYear(), TreeMap::new, toList()));
grouped.descendingMap().forEach((year, articles) ->
        list.add(new ArchiveListVo(year, articles)));
```

**预期效果**：从 N+1 次 SQL（N=年份数）降至 1 次

## 四、部署注意事项

1. **执行索引 SQL**：部署前需在生产数据库执行 `sql/add_performance_indexes.sql`（已在生产环境执行完毕）
2. **缓存清理**：部署后建议清除 Redis 中所有旧缓存 key（`sys_webconfig`、`notice:list`），让新缓存逻辑生效
3. **无需前端改动**：所有优化均为后端变更，API 返回格式不变
