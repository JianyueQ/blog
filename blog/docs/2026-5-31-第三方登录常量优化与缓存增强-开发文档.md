# 第三方登录常量优化与缓存增强 - 开发文档

> 日期：2026-05-31  
> 模块：mojian-commom / mojian-auth / mojian-api / mojian-admin

---

## 1. 背景与问题

### 1.1 硬编码域名问题

`Constants.java` 中第三方登录相关的重定向 URL 全部硬编码了域名：

```java
// 优化前
public static final String LOGIN_URL = "https://blog.jianyue.cloud/";
public static final String ADMIN_LOGIN_URL = "https://blog.jianyue.cloud/admin/login";
public static final String FRONT_BIND_SUCCESS_URL = "https://blog.jianyue.cloud/bindCallback?result=success";
// ... 共 8 个常量
```

**问题**：
- 域名变更时需要修改代码并重新编译部署
- 开发/测试/生产环境无法通过配置区分域名
- `sys_web_config` 表已有 `web_url` 字段，`sys_third_party_config` 表的 `redirect_url` 也是数据库存储，但 `Constants` 中仍然硬编码

### 1.2 缓存缺失问题

以下场景每次请求都直接查询数据库，存在不必要的 IO 延迟：

| 场景 | 方法 | 问题 |
|------|------|------|
| 用户登录 | `AuthServiceImpl.login()` | 每次登录查询 `slider_verify_switch` 配置 |
| 发送验证码 | `EmailUtil.sendCode()` | 每次发邮件查询 `sys_web_config` 获取站点信息 |
| 首页公告 | `HomeServiceImpl.getNotice()` | 每次访问首页查询公告列表 |

## 2. 优化方案

### 2.1 域名配置化

将域名提取到 `sys_config` 表中，通过 Redis 缓存提供高性能访问：

| config_key | config_value | 说明 |
|------------|-------------|------|
| `admin_base_url` | `https://blog.jianyue.cloud` | 后台管理系统基础 URL |
| `front_base_url` | `https://blog.jianyue.cloud` | 前台用户端基础 URL（生产环境） |

> **域名说明**：`blog.jianyue.cloud` 为生产环境域名，`gp.jianyue.cloud` 为测试环境域名。  
> 测试环境部署时需将 `front_base_url` 改为 `https://gp.jianyue.cloud`，同时确保 `sys_third_party_config` 表的 `redirect_url` 也使用测试域名。

`Constants.java` 中仅保留路径部分（不含域名）：

```java
// 优化后
public static final String FRONT_HOME_PATH = "/";
public static final String ADMIN_LOGIN_PATH = "/admin/login";
public static final String ADMIN_LOGIN_SUCCESS_PATH = "/admin/?token=";
public static final String FRONT_BIND_SUCCESS_PATH = "/bindCallback?result=success";
// ... 以此类推
```

运行时通过 `ConfigCacheService` 动态拼接完整 URL：

```java
configCacheService.getAdminBaseUrl() + Constants.ADMIN_LOGIN_PATH
// → https://blog.jianyue.cloud/admin/login
```

### 2.2 新增 ConfigCacheService

在 `mojian-commom` 模块新增 `ConfigCacheService`，提供统一的配置缓存访问：

```
com.mojian.service.ConfigCacheService
├── getConfigValue(configKey)  → 通用配置值查询（Redis缓存，1天过期）
├── getAdminBaseUrl()          → 后台站点URL（带降级默认值）
├── getFrontBaseUrl()          → 前台站点URL（带降级默认值）
├── getWebConfig()             → 网站配置对象（Redis缓存，1天过期）
└── evictConfigCache(key)      → 清除指定配置缓存
```

**缓存策略**：
- Redis Key 格式：`site_config:{configKey}`
- 过期时间：1 天（`DAY_EXPIRE = 86400s`）
- 降级策略：配置不存在时返回硬编码默认值，避免服务不可用

**缓存清理**：
- `SysConfigServiceImpl.update()` 修改配置时自动清除对应的 `site_config:` 缓存
- `SysWebConfigServiceImpl.update()` 修改网站配置时更新 `sys_webconfig` 缓存

## 3. 缓存优化详情

### 3.1 滑块验证码开关缓存

**优化前**（每次登录查 DB）：
```java
SysConfig verifySwitch = sysConfigMapper.selectOne(
    new LambdaQueryWrapper<SysConfig>()
        .eq(SysConfig::getConfigKey, "slider_verify_switch"));
```

**优化后**（Redis 缓存）：
```java
String verifyValue = configCacheService.getConfigValue("slider_verify_switch");
if ("Y".equals(verifyValue)) { ... }
```

### 3.2 邮件发送站点信息缓存

**优化前**（每次发邮件查 DB）：
```java
SysWebConfig webConfig = sysWebConfigMapper.selectOne(
    new LambdaQueryWrapper<SysWebConfig>().last("limit 1"));
```

**优化后**（复用 ConfigCacheService 缓存）：
```java
SysWebConfig webConfig = configCacheService.getWebConfig();
```

### 3.3 首页公告列表缓存

**优化前**（每次访问查 DB）：
```java
List<SysNotice> sysNotices = noticeMapper.selectList(...);
return sysNotices.stream().collect(Collectors.groupingBy(SysNotice::getPosition));
```

**优化后**（Redis 缓存，后台修改时自动清理）：
```java
// 读取：优先缓存
Object cached = redisUtil.get(RedisConstants.NOTICE_LIST_KEY);
if (cached != null) return 解析结果;
// 读取：降级查 DB + 写入缓存
redisUtil.set(NOTICE_LIST_KEY, JSON序列化, DAY_EXPIRE);

// 写入：SysNoticeServiceImpl 的 insert/update/delete 方法自动清缓存
redisUtil.delete(RedisConstants.NOTICE_LIST_KEY);
```

## 5. 缓存 Key 总览

| Redis Key | 过期时间 | 写入位置 | 清理位置 |
|-----------|---------|---------|---------|
| `site_config:{configKey}` | 1 天 | `ConfigCacheService.getConfigValue()` | `SysConfigServiceImpl.update()` |
| `sys_webconfig` | 永不过期 | `SysWebConfigServiceImpl.update()` | `SysWebConfigServiceImpl.update()`（覆盖写入） |
| `notice:list` | 1 天 | `HomeServiceImpl.getNotice()` | `SysNoticeServiceImpl` 的 insert/update/delete |
| `third_party_config::*` | Spring Cache 管理 | `SysThirdPartyConfigServiceImpl` | `update()` 时 `@CacheEvict` |

---

## 6. 部署注意事项

1. **执行 SQL**：部署前需执行 `sql/insert_site_url_config.sql`，插入 `admin_base_url` 和 `front_base_url` 配置
2. **环境适配**：生产环境两个 URL 均为 `https://blog.jianyue.cloud`；测试环境需将 `front_base_url` 改为 `https://gp.jianyue.cloud`
3. **回调地址一致性**：`sys_third_party_config` 表的 `redirect_url` 必须与当前环境域名一致，避免 OAuth 回调跳转到错误域名
4. **缓存清理**：如需立即生效修改域名，可通过后台修改 `sys_config` 表对应配置（会自动清缓存），或手动删除 Redis 中 `site_config:*` 相关键
